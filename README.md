# mcd-a11y-counter · 麦当劳适老与无障碍点餐台

**整个点餐过程只有三步。** 每一步：一次提问 → 一次回答 → 一个是否式确认。

```
第 1 步 · 定地方      给您看 1 家店        "是这家吗？"
第 2 步 · 定吃的      最多给您 3 个套餐    "要第一个吗？"
第 3 步 · 对一对      一张复述卡          "对了吗？"
```

没有第 4 步。

---

## 它面对的真实问题

实测麦当劳一家门店的菜单：**15 个分类、约 110 个 SKU**。

> 人气热卖 / 精选单人餐 / 鸡肉汉堡·卷 / 小食拼盘·多人餐 / 蘸酱炸鸡 / 随心配1+1 / 大堡口福 / 巨无霸牛鱼肉堡 / 安格斯MAX / 炸鸡 / 小食甜品·其他 / 开心乐园 / 麦咖啡™ / 500大卡套餐 / 饮品

对年轻用户这是信息丰富。对老年用户，这是噪音。

麦当劳 MCP 创意大赛已上榜的 128 个项目里，有 `mcd-voice-order-assistant`（15 Star）解决"用嘴代替手"的输入问题，但**零个项目**面向老年人、视障用户或低数字素养人群。

本 skill 不解决输入方式，解决的是**认知负荷**。

---

## 三步各解决了什么

### 第 1 步：把"找店"变成一个是否回答

- 优先查**收藏餐厅**（`searchType=1`）——老年人高频去同一家店，命中就跳过全部搜索过程
- `distance` 换算成走路分钟（**老年步速 50 米/分钟**，成年人经验值是 80）
- `businessStartTime/EndTime` 做营业校验，**支持跨夜门店**（18:00–06:00）
- **打烊倒计时**：≤30 分钟会主动说"再来不及了，要不要换一家"
- **> 800 米直接建议改送外送**

```
我们选这家店：

  麦当劳上海福州路餐厅

  福州路 666 号
  走路 5 分钟
  现在开门，到晚上 11 点

是这家吗？
```

不展示门店编号、不展示距离米数、不展示经纬度。

### 第 2 步：把 110 个 SKU 收敛到 3 个

优先 **`order-list` 复用上次**：

```
上次您点的是 板烧鸡腿堡套餐。
还是来这个吗？
```

答「好」→ **直接跳到第 3 步**，整个选餐环节消失。这是全 skill 里降负最强的一个动作。

没有历史订单时（实测新账号返回 `{"data":{}}`，属常态），静默降级到菜单收敛：

| 过滤 | 依据 | 理由 |
|---|---|---|
| 需购卡商品 | `canWithOrder=true` | 实测某店有 8 个，标价 28 元但不买卡享受不到 —— 典型误导 |
| 多人餐/分享餐 | 名称含「双人」「多人」「分享」「拼」 | 一人吃不完 |
| 新品 | `tags` 含「上新」 | 价高、口味不稳 |
| 非套餐 | `tags` 不含「套餐」 | 套餐一次解决主食+小食+饮料，避免拆成三次选择 |

三个候选要求**价差 ≥ 5 元**（实测存在 33.5 / 34 / 34.5 的连续价格，三选一毫无意义）。凑不满就给 1–2 个，不硬凑。

### 第 3 步：把"还能改什么"压到两个开关

```
要不要让店里少放点冰？
要不要让店里别放酱？
```

其余调整（换无糖、去生菜、去酸黄瓜、不加糖）——**用户提了才做**，绝不主动罗列。把 20 项调整摊开给老人看，前两步的降噪就白做了。

然后完整复述、算价、再确认一次，才下单。

## 子女模式：给爸妈的一张卡

最常见的实际场景不是老人自己用，而是**子女远程给父母点**。全部决策由子女完成，父母只需要收。

```
妈，给你点了麦当劳，一会送到家。

  送到：XX 小区 X 号楼 XXX
  到了：大概 30 分钟内，手机会响
  吃的：一个汉堡，一份薯条，一杯无糖可乐
  钱：我这边已经付过了，你不用付钱

  送到了就趁热吃。
  凉了用微波炉热 30 秒。
  不对打我电话。
```

「**你不用付钱**」是强制句 —— 老人最常见的顾虑是怕花了孩子的钱还要再付一次。

## 十二条无障碍规约

| # | 规则 |
|---:|---|
| 1 | 每步最多 **3 个**选项 |
| 2 | 每句 **≤ 15 字** |
| 3 | **不用表格**（读屏读表格是灾难），用缩进短行 |
| 4 | emoji 不承载关键信息，整轮 ≤ 2 个 |
| 5 | **不用缩写**：说「开车不用下车」不说「DT」 |
| 6 | 金额写「**34 元 5 角**」不写「¥34.5」 |
| 7 | 距离写「**走路 5 分钟**」不写「235 米」 |
| 8 | 每步**是否式**确认，不用开放式提问 |
| 9 | 每步**可回退** |
| 10 | **不用符号分隔**：避免 `→` `·` `|` `/`；套餐名「1+1」写作「一一」 |
| 11 | **避免英文与拼音** |
| 12 | 默认保守：小份、无糖、少冰、低钠 |

## 本次开发实测到的十四个坑（都已固化）

前六条来自结构分析，**后八条是真实调用跑出来的**（含深圳真实地址跑通模式 B）：

| # | 事实 | 后果 |
|---:|---|---|
| 1 | 套餐**顶层** `supportModify` 实测为 `false`，但配料的 `choices[].supportModify` 是 `true` | 只看顶层会误判"改不了" |
| 2 | 含 `unselectedKey` 的特调组，**所有项都要传给算价/下单**（未选中传 `unselectedKey`） | 少传会配错餐 |
| 3 | 冰量组**没有** `unselectedKey`，只传选中那项的 `selectedKey` | 当 A 类处理会出错 |
| 4 | 换**无糖可口可乐** `diffPrice = + ¥0` | 控糖老人换无糖**不加钱**，可当默认动作 |
| 5 | `diffPrice` 是「元」字符串，`values[].price` 是「分」整数 | 两套单位，混淆会算错钱 |
| 6 | `order-list`、`delivery-query-addresses` 实测均返回**空** | 无历史/无地址是常态，必须静默降级 |
| **7** | `roundList[].round` 填 `rounds[].id` 的**字符串形式**（`"1"`），不是 name | 填 name 会算价失败 |
| **8** | `modification.values[]` 里 **`key` 决定状态、`quantity` 决定份数**，两者都要给 | 去掉一项要写成 `{key: unselectedKey, quantity: 0}` |
| **9** | `calculate-price` 返回价格**单位是分**（`enjoyed.realDiscount` 例外，是元） | 不 ÷100 会把 34.5 元显示成 3450 元 |
| **10** | 到店场景返回 **`takeWayList`**（`eat-in` 堂食 / `locker-out` 外带），下单需携带 code | 漏传下单失败 |
| **11** | `delivery-create-address` 的 `address` 与 `addressDetail` **是两个字段**；`gender` 选填且填「先生/女士」 | 合并填不合规范；性别一律不追问 |
| **12** | **外送与到店是两套 code、两套价**（板烧 `1406`/23.5 → 外送 `901406`/26） | 换模式必须重新查菜单与详情 |
| **13** | **外送有配送费 + 打包费**（实测 +6.00 +1.90，比标价贵 25%） | 只报商品价会让父母以为被多收钱 |
| **14** | **「去酱」不是所有套餐都有** —— 麦乐鸡套餐的主食与小食均 `supportModify=false` | 写死两个开关会承诺做不到的事 |

### 已实跑验证的算价请求（深圳，模式 B）

```jsonc
{"storeCode":"1450713","orderType":1,"beType":1,
 "items":[{"productCode":"9900004064","quantity":1,"roundList":[
   {"round":"1","comboItemList":[{"code":"1406","quantity":1,
     "modification":{"values":[
       {"code":"102201","key":"0-0","quantity":0},     // 去酱
       {"code":"120512","key":"0-1","quantity":1}]}]}}, // 留生菜
   {"round":"2","comboItemList":[{"code":"4810","quantity":1}]},    // 中薯条
   {"round":"3","comboItemList":[{"code":"3050","quantity":1,
     "modification":{"values":[{"code":"200002","key":"1-1","quantity":1}]}]}}  // 少冰
 ]}]}
```

返回 `price: 3450` → **34 元 5 角**。

把 round 3 的 `code` 换成 `3071`（无糖可乐），`price` **仍是 3450** —— 零差价实证成立。

## 模式 B 已用真实账号跑通（深圳）

| 步骤 | 调用 | 结果 |
|---|---|---|
| 1 | `delivery-query-addresses` | `{"addresses":[]}` —— 无地址 |
| 2 | `delivery-create-address` | ✅ 建成功；`fullAddress` 被系统**自动补全了街道与门牌前缀** |
| 3 | `delivery-query-stores(beType=2)` | 3 家可配送，选同小区那家 `1421184` / `142118402`（另两家是 24 小时店） |
| 4 | `query-meals` | 外送菜单 13 个分类 |
| 5 | 四道过滤 → 三选一 | 麦乐鸡套餐 31 / 酥酥多笋卷套餐 39 / 巨无霸套餐 44 |
| 6 | `query-meal-detail` | 见下方「炸鸡类没有酱可调」 |
| 7 | `calculate-price` | `price: 3890` → **38 元 9 角** |

### 跑出来的三个意外

**① 外送与到店是两套 code、两套价**

| 餐品 | 到店 | 外送 |
|---|---:|---:|
| 板烧鸡腿堡 | `1406` / 23.5 | `901406` / 26 |
| 无糖可乐中杯 | `3071` / 9.5 | `903071` / 11 |

换模式就要重新查，不能复用 code。

**② 实付比标价贵 25%**

```
商品    31.00
配送费   6.00
打包费   1.90
─────────────
实付    38.90
```

只报商品价会让父母以为被多收了钱——复述卡必须拆开说。

**③ 炸鸡类套餐没有「去酱」**

`麦乐鸡(5块)中套餐` 的 round1（麦乐鸡）和 round2（小食）**全部 `supportModify=false`**，只有饮料能改。
原来写死的「少冰 + 去酱」两个开关在它是错的——对用户承诺系统做不到的事，比不问更糟。已改为「先查能给几个给几个，上限两个」。

### 到 `create-order` 前停下

链路已验证到算价。**没有调用 `create-order`** —— 涉及真实资金，按设计要等两次确认。

详见 [`MCP_INTEGRATION.md §6`](./MCP_INTEGRATION.md) 与 [`references/modification-guide.md`](./references/modification-guide.md)。

## 安装

**前置条件**：申请麦当劳中国 MCP Token。

WorkBuddy 左侧边栏【专家·技能·连接器】→【连接器】→【自定义连接器】→【配置 MCP】：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

把 `${MCD_MCP_TOKEN}` 换成你的 Token，保存后启用。

然后把本目录复制到 `C:/Users/<你的用户名>/.workbuddy/skills/mcd-a11y-counter/`。

## 使用示例

```
你：帮我妈点一份麦当劳，她住XX小区，七十多了，血压有点高
```

→ 自动进模式 B；若无可配送地址则引导新建；`list-nutrition-foods` 过滤钠 > 800mg；三选一给套餐；最后生成给妈妈的卡片。

```
你：我自己在人民广场，想吃麦当劳
```

→ 模式 A；查收藏，无则用位置搜索；取最近的一家；换算走路分钟；校验营业。

```
你：上次那个再来一份
```

→ `order-list` 命中 → 一句话确认 → 直接进第 3 步。

## 边界

- 不做优惠最优组合（榜单已有 25+ 个此类项目，且会让流程变复杂）
- 不做疾病诊断与营养治疗（只用 `sodium > 800mg` 做保守过滤）
- 不做生日派对预约
- 不调用积分、抽奖、会员卡相关接口

主动放弃这些是有意为之 —— 每一样都会引入新的决策点。
